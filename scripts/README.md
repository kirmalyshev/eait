# scripts/

Dev/ops helpers — not part of the bot runtime. Run with `bun run scripts/<name>.ts`.

- `setup.sh` — **the entrypoint for self-hosters.** Prerequisites → dependencies → test → `.env` → optional smoke test → optional service install. Idempotent; never overwrites `.env` without asking; reads secrets with echo off and never prints them back. `--help` for usage; `EAIT_NONINTERACTIVE=1` with the vars in the environment for provisioning.
- `smoke-openrouter.ts` — manual smoke test: sends one real image to the configured model and prints the raw output. Verifies OpenRouter + whatever `LLM_MODEL` resolves to (default lives in `src/config.ts`) does vision + structured output. **Run this before relying on the model** (needs a real `OPENROUTER_API_KEY`; makes a real network + billed call). Also `bun run smoke`.
- `service.sh` — run eait as a persistent service, **macOS (launchd) or Linux (systemd user unit)**: `scripts/service.sh {install|start|stop|restart|status|logs|uninstall}`. Generates the unit locally (no machine paths committed); logs → `logs/`. On macOS `status` also reports the last exit code, because `launchctl list` shows a crash-looping service as loaded.
- `eval-meals.ts` — **manual, billed** accuracy eval (issue #6): runs every fixture in the gitignored `eval/` dir (`<name>.{jpg,png,…}` + `<name>.json` with kitchen-scale ground truth, `kcal` required, macros/`total_grams` optional) through one or more OpenRouter models and prints, per model, kcal/macro MAE and MAPE, portion error, **signed bias** (is the model systematically high, and is that the portion or the richness?), and run-to-run spread. `--dir` selects the fixture dir (default `eval`), `--models a,b` to A/B, `--runs 3` for variance, `--mode prompt` to compare providers that reject OpenRouter's `response_format` json_schema (several Chinese vision models — grok/OpenAI-style keep working; `--mode schema` is the production default). Every output line carries its own case count, and a `coverage:` line reports what was excluded (refusals vs failures vs thinned runs) — **on stdout**, so a redirected report keeps its caveats. Exit codes: `2` bad arguments, `1` no usable fixtures, `3` ran but coverage was incomplete (numbers still printed, just not comparable across models). Metric logic lives in `src/eval.ts` (unit-tested); this is the I/O + spend shell.

  **Reading the bias line.** Bias is a geometric mean of estimate ÷ truth, so it says *direction*, which MAE and MAPE cannot. It is the number that caught the prompt's round-up hedge: grok-4.5 over-portioned by +28.5%, and deleting the "when torn, take the larger" line moved kcal MAE 149.3 → 125.0 (MAPE 49.2% → 42.2%). Before adding any instruction that pushes estimates one way, measure which way the model already errs.
- `fetch-nutrition5k.ts` — **public, unbilled**: populate `eval/` with a [Nutrition5k](https://github.com/google-research-datasets/Nutrition5k) sample (overhead RGB photo + dish macros) as a zero-effort accuracy **baseline** for the model A/B (#7), pending real weighed home meals (#6). Writes `<dish>.png` + `<dish>.json` into gitignored `eval/`; idempotent, `--n` sets sample size (default 30), `--min-kcal` (default 150) drops tiny single-ingredient plates so kcal MAPE stays meaningful. Prereq: `dish_metadata_cafe{1,2}.csv` in `eval/_meta/` (the script prints the `curl` to fetch them if missing). Western-cafeteria food → measures model capability, **not** eait's Russian/German home cuisine, which stays the real-meal calibration layer. CC BY 4.0 (Thames et al., CVPR 2021). Maps via `nutrition5kRowToExpectation` in `src/eval.ts` (unit-tested).
- `add-fixture.ts` — **free, offline**: record ONE weighed meal as an eval fixture (#6). Takes a photo plus the kitchen-scale weights (`"chicken breast: 180"`, table lookup) and writes `<dir>/<name>.<ext>` + `<dir>/<name>.json`. Composite or branded foods give their package label inline instead (`"pelmeni: 250 @ 275"`, or `@ kcal/protein/carbs/fat`) — the table carries single ingredients only, so a generic row can never stand in for a product you are holding. Prints each component's **share of the meal's calories**, which is what makes a mistyped weight visible; warns outside 0.2–6 kcal/g; refuses to overwrite an existing fixture without `--force`; copies the photo, never moves it. Flags: `--photo <path>` (required), `--name <stem>` (defaults to the photo's filename), `--dir <dir>` (default `eval`), `--force`, `--dry-run`, `--foods`. **Prefer `--dir eval/weighed`** — plain `eval/` is also `fetch-nutrition5k.ts`'s output, and one aggregate over both mixes cafeteria trays with home meals. Exit codes match `eval-meals.ts`: `2` bad arguments, `1` good arguments but the world was not as required. Arguments are parsed by a single tested pass (`src/argv.ts`), so an unknown flag, a repeated valued flag, or a missing value is an **error** rather than a silently dropped weighed component. An unknown ingredient is an **error with suggestions**, never a silent zero — a zeroed component would understate the ground truth and surface later as fake model over-estimation. Composition logic lives in `src/fixture.ts` (unit-tested, incl. an Atwater consistency check over every table row). **Capture protocol: `docs/ACCURACY_EVAL.md`.**
- `fetch-nutritionverse.ts` — **public, unbilled**: turn a [NutritionVerse-Real](https://www.kaggle.com/datasets/nutritionverse/nutritionverse-real) archive into fixtures — the closest public proxy for how eait is actually used, because its photos are **handheld iPhone shots at random angles** of real composed dishes (1–7 ingredients) whose every ingredient was weighed. Nutrition5k, by contrast, is a fixed overhead rig on cafeteria trays. Needs the ~1.1 GB zip once (`--archive`, no Kaggle account — the script prints the curl); streams individual entries with `unzip -p` rather than expanding it. `--n` (default 30), `--min-kcal` (default 150), `--dir` (default `eval/nutritionverse`, a subdirectory so it is never averaged with Nutrition5k). **Drops dishes whose photo disagrees with its ground truth** — a few rows in the archive pair a photo with an unrelated meal's numbers (dish 2 is an apple described as bread and lobster), which nothing else would catch because the numbers are well-formed and meal-sized. The gate compares the archive's own segmentation labels against the ingredient columns (`labelsAgree` in `src/eval.ts`, unit-tested). **CC BY-NC-SA 4.0 — non-commercial**; fixtures stay gitignored and are never redistributed.
- `fetch-food-db.ts` — **free, offline after download, no key**: build the local food-composition table (#8). Two sources: [USDA FoodData Central](https://fdc.nal.usda.gov/) (SR Legacy + Foundation, **public domain**) and [UK CoFID](https://www.gov.uk/government/publications/composition-of-foods-integrated-dataset-cofid) (**Open Government Licence v3 — attribution required**). ~13 MB download → `data/food-db/foods.jsonl`, 10,780 foods per 100 g. CoFID is what makes DISHES resolvable at all — "Lasagne, homemade", "Shepherd's pie, homemade", "Chilli con carne, homemade" — since USDA is an ingredient table and a meal photo shows dishes. Its `.xlsx` is parsed directly (open XML in a zip, `parseXlsxSheet`), and the sheet is located by NAME via workbook rels, never by file number. `--sources`, `--out`, `--cache`, `--refresh`, `--keep-archives`. Filters on `data_type`, which is load-bearing: the Foundation archive holds 411 real foods among 74k lab sub-samples and acquisition records. Parsing logic + English lookup live in `src/food_db.ts` (unit-tested). Not wired into the bot yet — see `docs/NUTRITION_DB.md`.
- `security-scan.ts` — repo safety gate (`bun run security`). Scans tracked files for secret patterns, personal-data leaks (operator id/name), and forbidden tracked files (`.env`). Exits non-zero on any finding. Runs in CI (`.github/workflows/security.yml`) and, once enabled, as a pre-commit hook: `git config core.hooksPath .githooks`.

## Security CI

- `.github/workflows/security.yml` — on push/PR/weekly: one `verify` job. Security gates run first (security-scan, then gitleaks over full history); typecheck, tests, `bun audit` and shellcheck follow under `if: always()`, so one failure does not hide the rest.
- `.github/dependabot.yml` — weekly bun (runtime deps) + GitHub-Actions updates.
- `.githooks/pre-commit` — local gate running **both** CI secret checks (`security-scan.ts` + `gitleaks git --staged`), so a leak is caught before it enters the history rather than after. The two are complementary: the custom scanner knows this repo's personal-data rules, gitleaks knows the vendor token formats. Enable with `git config core.hooksPath .githooks`. If gitleaks is not installed the hook says so and continues — CI still enforces it.
